The Theory You Need First

Every concept the code leans on, shortest form. If a file uses a word, it's defined here.

Part A · IPC and binder

Process isolation & IPC
Each Android app runs in its own process and can't touch another's memory. To ask a system service to do something (post a notification, start an activity), it must send a message across the process boundary — inter-process communication.
Binder
Android's main IPC mechanism. A kernel driver acts as the switchboard: a client hands it a message, it copies the message into the server process and wakes it. Almost every app↔system interaction is binder underneath.
/dev/binder & ioctl()
The driver is exposed as a device file. A process opens it once and does all binder traffic through one syscall: ioctl(fd, cmd, arg). That single chokepoint is why hooking ioctl catches everything.
BINDER_WRITE_READ
The one ioctl command that carries transactions. Its argument is a binder_write_read struct holding a write buffer (commands going to the kernel) and a read buffer (replies coming back). We only read the write buffer.
Command stream & binder_transaction_data
The write buffer isn't one message — it's a packed stream of commands, each a u32 code (BC_TRANSACTION, etc.) sometimes followed by a payload. A BC_TRANSACTION's payload is a binder_transaction_data, whose data.ptr.buffer points to the actual serialized arguments.

Part B · The wire format (serialization)

Parcel
Android's serialization container — a flat byte buffer written front-to-back. Method arguments are flattened into a Parcel on the way out and read back in the same order on the other side. Decoding is replaying those reads.
AIDL, proxy/stub, transaction code
Interfaces like INotificationManager are declared in AIDL; a tool generates a client proxy and server stub. Each method gets a numeric transaction code (our target, enqueueNotificationWithTag, is code 7). The proxy marshals args into a Parcel and calls transact(code, …).
Interface token
Every call starts with a small fixed header the proxy writes (strict-mode policy int, work-source uid int, an RPC header 'SYST', then the interface name as a string). The server checks it to reject malformed/mismatched calls. We read past it to reach the arguments.
String16 & UTF-16LE
Android native strings are UTF-16. On the wire: an int32 length in code units, then that many 2-byte little-endian units, then a 2-byte null, padded to 4. A length of −1 means a null string.
4-byte alignment & little-endian
Every Parcel item is padded so the next starts on a multiple of 4 — miss the padding and everything after reads as garbage. All values are little-endian, which on arm64 means a raw memcpy gives the right number.
Bundle & type-tagged values
A notification's extras are a Bundle (a key→value map). Each value is written as an int32 type tag then its payload — VAL_STRING (0) is just a string; VAL_CHARSEQUENCE (10) adds a "kind" int first. The title/text live under keys android.title and android.text.

Part C · Native linking (how the hook installs)

ELF & dynamic linking
Shared libraries (.so) are ELF files. When one library calls a function imported from another (libbinder calling libc's ioctl), the call goes indirectly through a pointer the dynamic linker fills in at load time.
GOT / PLT
That pointer lives in the Global Offset Table. Each imported function has one GOT slot holding its real address. Overwrite libbinder's ioctl slot with our function's address and every ioctl call libbinder makes jumps to us first — no instruction rewriting needed.
Symbols, strings, relocations, base address
To find which slot is ioctl we read ELF tables: relocations tie a slot to a symbol, the symbol names an offset into a string blob. Every table address is file-relative, so we add the library's runtime base address to get the real pointer.
RELRO & mprotect
The linker marks the GOT read-only after startup (RELRO) to resist exactly this trick. We call mprotect to make that memory page writable again before the swap.
Constructor & .so injection
A function marked __attribute__((constructor)) runs automatically when the .so loads. A separate injector uses ptrace to make the already-running app dlopen our library, which fires that constructor — and the hook installs itself.
