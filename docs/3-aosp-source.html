Where Binder Lives in the Source

When you want the real behavior instead of a summary.

Browse it at cs.android.com (Android Code Search) — pin a branch like android13-release to match the emulator. Paths drift slightly between versions; the file names are stable.

Kernel driver — the structs we include

  • include/uapi/linux/android/binder.h
    The exact header our hook #includes. Defines binder_write_read, binder_transaction_data, BINDER_WRITE_READ, and the BC_*/BR_* command codes.
  • drivers/android/binder.c
    The driver itself: how it parses the write command stream and copies a transaction into the target process. The other side of our ioctl.

Native libbinder — the call we hook & the wire format

frameworks/native/libs/binder/
  • IPCThreadState.cpp
    talkWithDriver() is the literal ioctl(fd, BINDER_WRITE_READ, &bwr) we intercept; writeTransactionData() builds the binder_transaction_data we walk to.
  • ProcessState.cpp
    Opens /dev/binder — the fd everything flows through.
  • Parcel.cpp
    The native side of serialization: writeInterfaceToken (the 'SYST' header via B_PACK_CHARS), writeString16, and the 4-byte padding we re-implement in parcel.c.

Java framework — Parcel values, Bundle, Notification

frameworks/base/core/java/android/
  • os/Parcel.java
    The VAL_STRING = 0 / VAL_CHARSEQUENCE = 10 constants and the writeValue/readValue switch — exactly the type tags bundle.c branches on.
  • os/BaseBundle.java, os/Bundle.java
    How a Bundle flattens its key→value map into a Parcel (the thing we scan instead of parsing).
  • text/TextUtils.java
    writeToParcel(CharSequence,…) — writes the "kind" int before the string, the one we skip in the VAL_CHARSEQUENCE branch.
  • app/Notification.java
    writeToParcel, and the key constants EXTRA_TITLE = "android.title" and EXTRA_TEXT = "android.text".
  • app/INotificationManager.aidl
    The method signature enqueueNotificationWithTag(String, String, String, int, in Notification, int), and the ordering that gives it transaction code 7.

The glue

  • system/tools/aidl
    The AIDL compiler that generates the proxy/stub, emits the writeInterfaceToken prefix, and numbers the transactions (onTransact switch).
  • services/core/java/com/android/server/notification/NotificationManagerService.java
    The server end — what actually receives and handles the transaction we're sniffing.

These pointers are from AOSP as I know it, not a checkout — file names are reliable; confirm exact line numbers and method names on cs.android.com.
