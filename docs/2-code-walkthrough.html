The five pieces that make it work — the rest in one line each.

This is the focused read: the headline mechanism (the GOT swap) and the four decode steps that carry the logic. The trivial plumbing is summarized at the end so nothing's a mystery, without spending a page on each.

The one picture

APP ──ioctl()──► [ my_ioctl ] ──► real_ioctl() ──► KERNEL (/dev/binder) │ │ request == BINDER_WRITE_READ ? ▼ bs_capture_bwr() hook/capture.c │ walk the command stream │ for each BC_TRANSACTION: │ follow data.ptr.buffer → the Parcel bytes │ is_notification()? (scan for INotificationManager) ▼ bs_decode_enqueue(bytes, len, &notif) decoder/src/svc_notification.c │ ┌─────────────┼───────────────────────────┐ ▼ ▼ ▼ interface token leading AIDL args extras Bundle lookup token.c parcel.c (String16) bundle.c → android.title / android.text │ ▼ __android_log_print(...) → adb logcat -s binder-sniffer

Two halves: capture (live, in the app) and decode (pure C, no I/O — runs both on-device and offline against a saved capture). Below: the swap that installs the hook, then the decode in the order the bytes arrive.

The mechanism — the GOT swap

hook/bshook.c

The whole trick: libbinder calls ioctl indirectly through one pointer in its Global Offset Table. Overwrite that pointer with ours and every binder call passes through us first.

typedef int (*ioctl_fn)(int, unsigned long, ...);
static ioctl_fn real_ioctl = NULL;

static int my_ioctl(int fd, unsigned long request, void *arg) {
    if (request == BINDER_WRITE_READ && arg) {
        bs_capture_bwr((const struct binder_write_read *)arg);
    }
    return real_ioctl(fd, request, arg);   // always forward
}

A load-time constructor finds the slot and swaps it:

real_ioctl = (ioctl_fn) *got_slot;   // save the original
*got_slot  = &(my_ioctl);            // redirect to ours
  1. Finding the slot (the ELF legwork): a __attribute__((constructor)) runs when the .so loads; it uses dl_iterate_phdr to locate libbinder, walks its PT_DYNAMIC table for the symbol/string/relocation tables, and scans relocations for the one named "ioctl". That relocation's offset (plus the load base) is got_slot.
  2. mprotect past RELRO. The GOT is read-only after startup, so we round the slot down to its page and mprotect it read+write before the swap.
  3. Save, then redirect. Two lines: stash the real ioctl in a global, point the slot at my_ioctl. From now on my_ioctl runs first and always forwards, so the app never notices.
  4. Why GOT patching? No instruction rewriting, no trampolines — flip one pointer, and uninstall by restoring it.

The live walk

hook/capture.c

On each BINDER_WRITE_READ we walk the outgoing command stream, find transactions, and hand matching Parcels to the decoder.

void bs_capture_bwr(const struct binder_write_read *bwr) {
    uintptr_t base = (uintptr_t)bwr->write_buffer;
    size_t off = 0;
    while (off + 4 <= (size_t)bwr->write_size) {
        uint32_t cmd = *(uint32_t *)(base + off);
        uint32_t payload = BC_PAYLOAD_SIZE(cmd);   // (cmd >> 16) & 0x3FFF
        off += 4;
        if (cmd == BC_TRANSACTION || cmd == BC_TRANSACTION_SG) {
            const struct binder_transaction_data *btd =
                (const struct binder_transaction_data *)(base + off);
            const uint8_t *parcel = (const uint8_t *)btd->data.ptr.buffer;
            size_t len = (size_t)btd->data_size;
            if (is_notification(parcel, len))         // UTF-16 scan, first 256B
                log_notification(btd, parcel, len);   // decode + __android_log_print
        }
        off += payload;
    }
}
  1. The write buffer is a packed stream of commands, not one message — so we loop. Each command's payload size is encoded in its own code (the _IOC_SIZE field), which is how we step without a lookup table.
  2. The Parcel isn't inline. btd->data.ptr.buffer is a pointer to the payload elsewhere in memory; we follow it. It's valid because we're in the app's own address space during its ioctl.
  3. Filter, then decode. is_notification scans the first 256 bytes for INotificationManager; only matches reach the decoder. log_notification runs bs_decode_enqueue and logs — the decoder is read-only, so it's safe here, and logging goes to logd over a socket (not /dev/binder), so it can't re-enter the hook.

The wire format that matters

decoder/src/parcel.c

A Parcel is numbers and strings end to end, each padded to 4 bytes. The one primitive worth studying is the string reader — everything else is a bounds-checked memcpy.

int bs_read_string16(bs_parcel *p, char *out, size_t outcap) {
    int32_t len = bs_read_i32(p);          // code units, or -1 = null string
    if (p->error) return 1;
    if (len < 0) { if (outcap) out[0] = 0; return 0; }
    size_t nbytes = (size_t)(len + 1) * 2;   // len UTF-16 units + null terminator
    if (!ensure(p, nbytes)) return 1;
    size_t o = 0;
    for (int32_t i = 0; i < len; i++) {
        uint16_t c;
        memcpy(&c, p->data + p->pos + (size_t)i * 2, 2);
        if (o + 1 < outcap) out[o++] = (c < 0x80) ? (char)c : '?';   // UTF-16 → ASCII
    }
    if (outcap) out[o] = 0;
    p->pos += nbytes;        // consume chars + null terminator
    bs_align4(p);            // step over padding to the next 4-byte boundary
    return 0;
}
  1. String16 on the wire: an int32 length in code units, then that many 2-byte little-endian units, a 2-byte null, then padding to 4. -1 means a null string.
  2. Alignment is the classic bug. After a string, the next item starts on a multiple of 4; forget bs_align4 and everything after reads as garbage.
  3. Bounds are handled once. Every read goes through ensure(), which latches an error flag on overflow so a malformed Parcel yields empty output, never a crash.

The clever shortcut

decoder/src/bundle.c

Rather than parse the whole Notification object field-by-field (version-fragile), we scan the bytes for the key and decode the value right after it.

// find the key as UTF-16LE, requiring a null terminator after the match
// so "android.text" doesn't match the start of "android.textLines"
static long find_key_utf16(const uint8_t *buf, size_t len, const char *s) { ... }

int bs_bundle_get_charseq(const bs_parcel *whole, const char *key,
                          char *out, size_t outcap) {
    long chars = find_key_utf16(whole->data, whole->size, key);
    if (chars < 0) return 1;
    size_t pos = (size_t)chars + strlen(key) * 2 + 2;   // past chars + null
    pos = (pos + 3u) & ~((size_t)3u);                    // align to 4

    bs_parcel p; bs_parcel_init(&p, whole->data, whole->size); p.pos = pos;
    int32_t vtype = bs_read_i32(&p);
    if (vtype == VAL_CHARSEQUENCE) { (void)bs_read_i32(&p); /* kind */ }
    return bs_read_string16(&p, out, outcap);            // the actual text
}
  1. Scan, don't parse. Slide over the buffer matching the key in UTF-16; the null-terminator check is what prevents false prefixes. Returns where the key's chars start.
  2. The value is a tagged union. An int32 type tag, then the payload: VAL_STRING (0) is a bare String16; VAL_CHARSEQUENCE (10) inserts one "kind" int first. Either way it ends in the String16 we want.
  3. This is the one deliberate rigor-for-simplicity trade — reliable because android.title/android.text are distinctive, but not a real Bundle parse.

The whole decode in one function

decoder/src/svc_notification.c

Everything above, assembled. Read it and you can see the strategy switch mid-function.

int bs_decode_enqueue(const uint8_t *buf, size_t len, bs_notif *out) {
    memset(out, 0, sizeof(*out));
    bs_parcel p; bs_parcel_init(&p, buf, len);

    // 1. header + the AIDL args, read IN ORDER
    bs_read_interface_token(&p, out->interface, sizeof(out->interface));
    bs_read_string16(&p, out->pkg, sizeof(out->pkg));   // pkg (kept)
    bs_skip_string16(&p);                                // opPkg
    bs_skip_string16(&p);                                // tag
    (void)bs_read_i32(&p);                               // id
    if (p.error) return 1;
    // the Notification parcelable + userId follow — we don't walk them

    // 2. title/text by SCANNING the extras (a second, whole-buffer cursor)
    bs_parcel whole; bs_parcel_init(&whole, buf, len);
    out->have_title = (bs_bundle_get_charseq(&whole, "android.title", out->title, sizeof(out->title)) == 0);
    out->have_text  = (bs_bundle_get_charseq(&whole, "android.text",  out->text,  sizeof(out->text))  == 0);
    return 0;
}
  1. Two strategies, one function. Ordered reading for the fixed prefix (token, then args in declaration order), then a second whole-buffer cursor that scans for the deep extras. That split is the key design decision.
  2. Order is everything in step 1. Each call consumes exactly its bytes so the next starts correctly — keep pkg, skip opPkg/tag, discard id.
  3. We stop before the Notification parcelable on purpose — walking it field-by-field is the fragile part, so the scan in step 2 does the job instead.

The supporting cast (one line each)

Real code, but nothing surprising — here so the picture is complete.

  • decoder/include/bs_decoder.h — the two shapes: a bs_parcel cursor (data/size/pos + a latching error) and a fixed-size bs_notif result. No malloc anywhere.
  • bs_read_i32 / bs_read_i64 / ensure — the base readers: bounds-check, memcpy (safe for unaligned, little-endian on arm64), advance pos.
  • bs_align4 / bs_skip_string16 — round pos up to a multiple of 4; skip a string's bytes without copying when we don't need its value.
  • decoder/src/token.c — the interface token: read past three int32s (strict-mode, work-source, the 'SYST' header), then the descriptor String16.
  • hook/capture.c · is_notification — a UTF-16 substring scan of the first 256 bytes for INotificationManager.
  • tests/host_decode.c — the offline driver: read a .bin into memory, call the same bs_decode_enqueue, print the result. Proves the decoder has no device dependency.
